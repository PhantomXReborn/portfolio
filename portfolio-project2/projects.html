Technical Documentation

architecture evolution

Assignment #1 utilized a pure MVC approach where the browser handled all state. Assignment #2 decoupled the frontend from the backend. The client is now a "dumb terminal" that only renders UI, while all rules and state live on the server.

  • Lab 07 (Client): Separate JS modules for dice.js, engine.js, game.js.
  • Assignment #2 (Server): server.js acts as a state machine. app.js purely uses Fetch API.

rest api endpoints (Assignment 2)

These endpoints process all game logic on the server, preventing client-side cheating.

MethodEndpointPurpose
POST/api/gameCreate a new game session
GET/api/game/:idFetch current state snapshot
POST/api/game/:id/rollRoll un-held dice
PUT/api/game/:id/holdToggle hold state on a die
POST/api/game/:id/scoreRecord a score and end turn

highlights & challenges

  • Server-authoritative state — rules and rolls run on the server to prevent cheating.
  • Stateless scoring engine — yatzyEngine.js receives a score table and returns a calculation, so concurrent games don't collide.
  • Async UX — CSS dice animation plays while awaiting the server response, hiding network latency.
  • Responsive design — CSS Grid + media queries for tablet and mobile.
  • Accessibility — ARIA labels on dice, focus-visible outlines, keyboard-escapable modals.
